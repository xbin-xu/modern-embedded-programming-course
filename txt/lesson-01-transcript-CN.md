# 第1课：计数 / Lesson 1: Counting

Welcome to the Embedded Systems Programming course. My name is Miro Samek and in this lesson I'm going to show you how computers count. Here and throughout this course I'm going to use the free evaluation version of the IAR tool set that we have downloaded and installed in lesson zero.

欢迎来到嵌入式系统编程课程。我是 Miro Samek，这节课我来给你讲讲计算机是怎么计数的。本课程以及后续所有课程中，我都会使用我们在第 0 课中下载安装的 IAR 工具集免费评估版。

---

To create your first project, launch IAR EWARM and select Project > Create New Project menu. Expand the C project types, select Main, and click OK. This opens the file explorer where you need to choose the directory for your project.

创建你的第一个项目：启动 IAR EWARM，选择 Project > Create New Project 菜单。展开 C 项目类型，选 Main，点 OK。这时会弹出文件浏览器，让你选择项目存放的目录。

---

I recommend that you create the "embedded-programming" directory on your C drive for the entire course, within which you will add subdirectories for each lesson. To do this, click on the C drive and then click on New Folder. Next, double click on the newly created folder and create the subdirectory "lesson1" for this lesson. Double click on the "lesson1" subdirectory to get inside it and type the name of the project. For this course, name this project generically "project". Finally, click Save.

我建议你在 C 盘上建一个 "embedded-programming" 目录，整个课程都用它，里面再为每节课建一个子目录。做法是：点 C 盘，点 New Folder。然后双击刚建的文件夹，为本课创建子目录 "lesson1"。再双击 "lesson1" 进去，输入项目名称。本课程统一把项目命名为 "project"。最后点 Save。

---

As you can see, the project contains a generated `main.c` file, which I will explain in a minute. But first, let's check how the directories and files look on the disk.

如你所见，项目里有一个自动生成的 `main.c` 文件，我稍后会解释它。不过先来看看磁盘上的目录和文件结构。

---

To finish configuring your project, you need to adjust a few parameters. Click on the Project > Options menu. In the Target tab, you need to adjust the processor variant. Select Device and click on the selection button. Choose Texas Instruments > LM4F > LM4F120H5QR device.

要完成项目配置，还需要调几个参数。点 Project > Options 菜单，在 Target 选项卡里调整处理器型号。选 Device，点选择按钮，然后选 Texas Instruments > LM4F > LM4F120H5QR。

---

Next, select the C/C++ Compiler category. Here you can see that the default language is C and that the C dialect is C99. In this course I will teach you this newer dialect of C.

接下来选 C/C++ Compiler 类别。可以看到默认语言是 C，C 方言是 C99。本课程我就教你这个较新的 C 语言标准。

---

Finally, click on the Optimizations tab and make sure that the optimization level is set to Low, which is the default. A couple of our first programs won't work correctly at higher optimization levels, until I show you how to write code that works even if highly optimized.

最后点 Optimizations 选项卡，确认优化级别设为 Low，这也是默认值。我们最初几个程序在更高优化级别下会出问题，直到后面我教你如何写出在高优化下也能正确运行的代码。

---

As you are running the IAR tool set for the first time, you should also spend a minute to tailor it to your preferences. Click on Tools > Options menu. Here you can change the fonts, for example I prefer my fixed width font to be Lucida Console. In the Editor section, increase the indentation to four spaces and select spaces instead of tabs. I strongly recommend avoiding tabs in your code, because they are rendered differently on different devices such as printers.

既然是第一次运行 IAR 工具集，花一分钟按你的喜好做些定制吧。点 Tools > Options 菜单，在这里可以改字体，比如我喜欢把等宽字体设成 Lucida Console。在 Editor 部分，把缩进改成四个空格，并且选空格代替制表符。我强烈建议代码中不要用制表符，因为它们在不同设备上（比如打印机）显示效果不一样。

---

So finally we can get to the code generated by the IAR tool set. Let's try first to validate that this indeed is a valid C code. You do this by compiling the code, that is, running it through a program called the **compiler**. In the Project menu, select the Make option and note that its keyboard shortcut is F7. You will use the F7 shortcut quite frequently.

终于可以看看 IAR 工具集生成的代码了。先来验证一下这确实是合法的 C 代码。做法是**编译**（compiling）代码——也就是把它交给一个叫**编译器**（compiler）的程序来处理。在 Project 菜单里选 Make，注意它的快捷键是 F7。以后你会非常频繁地用到 F7。

---

Since it is the first time you build this project, the tool asks for the workspace name. Type a generic name "workspace" and hit return. The build completes with zero errors and zero warnings. So, congratulations for your first legal C program.

由于是第一次构建这个项目，工具会问你工作区叫什么名字。输入一个通用名称 "workspace"，回车。构建完成——零错误，零警告。恭喜，你的第一个合法 C 程序诞生了。

---

Now let's reformat the generated code to use the line saver bracing placement and indentation of four spaces, which I prefer. The compiler doesn't really care about any of this formatting and would accept just as well the code formatted as one long line. But the formatting makes quite a big difference to humans who need to read and maintain the code.

接下来把生成的代码重新排版，用我喜欢的行尾花括号风格和四空格缩进。编译器根本不在乎这些格式，就算把代码写成一行它也照样接受。但格式对于需要阅读和维护代码的人来说，差别可就大了。

---

But obviously not everything you do to the code is legal C. For example, let's type something illegal and compile again by pressing F7. This time the compiler reports errors. When you double click on the error report, the tool set brings you right to the offending place in the code, which is rather cool.

但显然不是你写的所有东西都是合法的 C 代码。比如，随便打点非法的东西，再按 F7 编译一下。这次编译器报错了。双击错误信息，工具会直接跳到代码出错的位置，这个功能很赞。

---

After removing the problem, it's a good practice to ask the compiler to check you again by pressing F7. I'd like to convince you from the get-go that the compiler is your best friend, constantly watching over your shoulder. All you need to do is give him a chance to help you by frequently pressing F7.

改完问题之后，按 F7 让编译器再检查一遍，这是个好习惯。我想从一开始就让你明白：编译器是你最好的朋友，一直在你背后盯着。你要做的就是经常按 F7，给它一个帮你的机会。

---

Now let's define a **counter variable**, which I will use to show you how computers count. A **variable** is a location in computer memory to store a value such as a number. In C, you have to define a variable before you can use it. You do this by specifying the type of the variable followed by the name, and optionally the initial value.

现在来定义一个**计数器变量**（counter variable），我会用它来演示计算机如何计数。**变量**（variable）就是计算机内存中用来存值（比如数字）的一个位置。在 C 语言中，变量必须先定义才能使用——指定类型、名字，以及可选的初始值就行了。

---

According to my own advice, let's check right away if the compiler accepts the variable definition. Well, kind of. There are no errors, but there is one warning that the variable `counter` has been declared but never referenced. That's true, so let's move on.

按照我刚才的建议，马上看看编译器是否接受这个变量定义。嗯，差不多吧。没有错误，但有个警告说变量 `counter` 声明了却没被使用。确实如此，继续往下走。

---

Now let's **increment** the variable `counter` by one from its current value. C has a special operator `++` for it, called **pre-increment**. As usual, I let the compiler check that the code still compiles. As we want to watch how the computer will count, let's increment the counter several more times.

现在把变量 `counter` 从当前值**递增**（increment）一。C 语言有个专门的运算符 `++`，叫**前置递增**（pre-increment）。照例让编译器检查一下代码还能不能编过。既然我们要观察计算机怎么计数，那就再多递增几次。

---

Let's compile one last time by pressing F7. Now I will show you how to run this program. First, make sure that the project is configured for the simulator. Actually, you can tell it by the presence of the Simulator menu at the top. But to double check, click the Project > Options menu. In the category you should see the Simulator selection.

最后再按 F7 编译一次。现在我来教你如何运行这个程序。首先，确保项目配置的是**模拟器**（simulator）。其实看顶部有没有 Simulator 菜单就能判断。不放心的话，点 Project > Options 菜单，在类别里应该能看到 Simulator 选项。

---

You have two options to run the program: either through the Project > Download and Debug menu, or by the toolbar button, which I will use now. The IAR tool set has switched to the **debugger mode**. Let's make sure that the following debugger views are visible: Disassembly, Memory, Register, and Locals.

运行程序有两种方式：通过 Project > Download and Debug 菜单，或者用工具栏按钮。我现在用按钮。IAR 工具集已经切换到了**调试模式**（debugger mode）。先确保以下几个调试视图都打开了：Disassembly、Memory、Register 和 Locals。

---

Let's rearrange the debugger windows so we have the best view inside the simulated ARM Cortex-M4 processor.

把调试窗口重新排列一下，好让我们能最清楚地观察这个模拟的 ARM Cortex-M4 处理器内部。

---

First, let's take a look inside the Disassembly view. This view shows the **machine instructions** that the compiler generated from your program. The processor is stopped at the highlighted instruction, which is the beginning of your `main` function. The machine instructions, as anything else inside the computer, are just numbers. The symbols to the right of the instructions are so-called **instruction mnemonics** and are added by the debugger to improve readability. The column of numbers left to the instructions are the **memory addresses** of the instructions. Memory addresses are simply numbers assigned to bytes in memory.

先来看 Disassembly（反汇编）视图。这里显示的是编译器从你的程序生成的**机器指令**（machine instructions）。处理器停在高亮的那条指令上，也就是 `main` 函数的入口。机器指令跟计算机里其他所有东西一样，说白了就是数字。指令右边的符号叫做**指令助记符**（instruction mnemonics），是调试器为了方便阅读加上去的。指令左边那一列数字是**内存地址**（memory addresses）。内存地址就是分配给内存中每个字节的编号。

---

To convince you that the instructions are really just numbers in memory, let's take a look in the Memory view. You can think of memory as a big table of bytes, which are numbered sequentially starting from zero. These sequential numbers, called the **addresses**, are shown in the column of numbers along the left edge of the Memory view.

为了让你相信指令真的就是内存中的数字，我们来看看 Memory（内存）视图。你可以把内存想象成一张巨大的字节表，从零开始依次编号。这些编号就叫**地址**（addresses），显示在 Memory 视图左侧那一列数字里。

---

To better recognize the machine instructions in memory, let's change the view to 2-byte units, because most of the ARM Cortex-M instructions occupy two bytes in memory. Now you should easily recognize the instructions. For example, at address 0x40 you see the same number as in the Disassembly view. The same is true for instructions at addresses 0x42 through 0x50.

为了更容易认出内存中的机器指令，把视图切换成 2 字节单位，因为大部分 ARM Cortex-M 指令在内存中占两个字节。现在你应该很容易辨认这些指令了。比如在地址 0x40 处，你看到的数字跟 Disassembly 视图里一模一样。0x42 到 0x50 处的指令也是如此。

---

Alright, so let's step through the code one C line at a time. To do this, click inside the Code View and click on the Step Into button. As you can see, the current instruction advanced by one and the value of the `counter` variable changed to zero. Also, if you look carefully, the value of the **PC register** has changed to 0x42. PC stands for **Program Counter**, because it counts the instructions.

好，来逐行单步执行代码。点一下 Code View 内部，然后点 Step Into 按钮。如你所见，当前指令前进了一条，`counter` 变量的值变成了零。另外仔细看的话，**PC 寄存器**（PC register）的值变成了 0x42。PC 是**程序计数器**（Program Counter）的缩写，因为它就是用来计数指令的。

---

Now let's click the Step Into button again to execute the next instruction. This time the value of the variable `counter` has incremented to one. The Locals view tells you also that the `counter` variable is located in the R1 register. Indeed, when you check the Register view, you can see that the value of R1 is one.

再点一次 Step Into 执行下一条指令。这次 `counter` 变量的值递增到了一。Locals 视图还告诉你 `counter` 变量存放在 R1 寄存器里。没错，去看 Register 视图，R1 的值就是一。

---

But what are these **registers** anyway? Well, if you ever used a simple calculator, you already should have a good idea, because registers in a microprocessor are very similar to the calculator's memory register. Typically, you can add, recall, and clear the memory register of the calculator. The ARM Cortex-M processor has 16 such registers, which are named R0 through R15, whereas R15 is the other name of the PC. All these registers can hold 32-bit numbers.

那这些**寄存器**（registers）到底是什么呢？如果你用过简单的计算器，应该心里有数了——微处理器里的寄存器跟计算器的存储器非常像。通常你可以对计算器的存储器做加法、调用、清除操作。ARM Cortex-M 处理器有 16 个这样的寄存器，命名为 R0 到 R15，其中 R15 就是 PC 的另一个名字。所有这些寄存器都能存放 32 位的数字。

---

The importance of these registers lies in the fact that machine instructions can manipulate the registers directly, typically in just one clock cycle. You've already seen two examples of instructions manipulating registers: moving a zero to R1 and adding one to R1.

寄存器之所以重要，是因为机器指令能直接操作它们，通常只需要一个时钟周期。你已经见过两个操作寄存器的指令了：把零送进 R1，以及把 R1 加一。

---

And always, let's keep stepping through the code and watch the counter variable increment. Everything seems to work as expected, but something interesting happens when the counter reaches 10. As you recall, the counter is located in the R1 register, but at value 10, the Locals and the Register views seem to go out of sync, because R1 shows value 0xA. This requires some explanation.

继续单步执行，观察计数器递增。一切看起来都正常，但计数器到 10 的时候，有趣的事情来了。前面说过计数器在 R1 寄存器里，可当值为 10 时，Locals 和 Register 视图好像对不上了——R1 显示的是 0xA。这得解释一下。

---

The Locals view shows the value of C in the **decimal system**, which people adopted because regular people have 10 fingers. However, C programmers grow 16 fingers after a while on the job. Programmers find it much more natural to work in the **hexadecimal system**, because it maps perfectly to the **binary system** underlying all computers.

Locals 视图用的是**十进制**（decimal system）来显示值——人们用十进制是因为普通人有 10 根手指。不过 C 程序员干上一阵子就会"长出"16 根手指。程序员用**十六进制**（hexadecimal system）要自然得多，因为它跟所有计算机底层的**二进制**（binary system）完美对应。

---

As you can see in this comparison between decimal, binary, and hexadecimal, a single hexadecimal digit represents a group of four bits called the **nibble**. In contrast, the decimal system needs two digits for numbers above nine. The strange looking `0x` prefix in front of every hex number is the C language convention of encoding hex numbers.

看这个十进制、二进制和十六进制的对照表：一个十六进制数字代表四位二进制，这四位叫做一个**半字节**（nibble）。而十进制在 9 以上就需要两位了。每个十六进制数前面那个看起来怪怪的 `0x` 前缀，是 C 语言表示十六进制数的约定。

---

At the bottom of the picture, you can see an example of applying the table above to encode a string of 32 bits into hexadecimal. The bits are grouped in four packs of eight, which are called **bytes**. Each byte contains two 4-bit nibbles. As I just explained, the nibbles map directly to hex digits. For example, the nibble 1010 maps to the hex digit A, the nibble 0101 to hex digit 5, and so on. In the end, the whole 32-bit string is equivalent to hex `0x260F3E5A`.

图下方是一个把 32 位二进制串编码成十六进制的例子。这些位被分成四组，每组八位，叫做**字节**（bytes）。每个字节包含两个 4 位的半字节。刚才说过，半字节直接对应十六进制数字。比如半字节 1010 对应十六进制 A，0101 对应 5，以此类推。最终整个 32 位串就等于十六进制的 `0x260F3E5A`。

---

So now I hope that the debug views make much more sense to you, because most of them show hex numbers, as you can tell by the `0x` prefix. Now, before letting the program increment the counter, let's cheat a bit to test what happens when the number gets really big. That's actually very easy to do in the debugger, because you can manually change any variable by clicking on it and typing a new value. Type in `0x7FFFFFFF` and press return. This turns out to be a big number in decimal.

现在希望调试视图对你来说更有意义了——大部分视图都显示十六进制数，认那个 `0x` 前缀就行。在让程序继续递增之前，我们先做点弊，看看数字变得特别大会怎样。在调试器里这很容易做到：点一下变量，输入新值就行。输入 `0x7FFFFFFF`，回车。换算成十进制，这是一个非常大的数字。

---

Now let your program increment the counter by one. Whoops, something very strange happened. Your counter becomes a huge negative number in decimal, while it is `0x80000000` in the R1 register. Again, this requires some explanation.

现在让程序把计数器递增一。糟糕，出怪事了——计数器在十进制下变成了一个巨大的负数，而 R1 寄存器里的值是 `0x80000000`。这又得解释一下了。

---

The `counter` variable has been declared as an integer `int`, which in C is a **signed number**, meaning that it can hold both positive and negative values. It turns out that computers represent negative numbers in a rather peculiar way called the **two's complement representation**.

`counter` 变量被声明为 `int` 整数类型，在 C 语言中这是**有符号数**（signed number），也就是说它既能存正数也能存负数。计算机表示负数的方式相当独特，叫做**二进制补码**（two's complement representation）。

---

This circular graph explains how it works. Every arrow in the diagram represents increment by one. For small positive numbers, everything works as expected until the number fills all the bits but the most significant one. This is the **largest positive value** a 32-bit signed integer can represent. When you increment this number by one, you overflow to the most significant bit, at which point the number becomes negative. In fact, it becomes the **smallest negative number** you can represent with 32 bits. From there, when you keep incrementing, the value becomes less negative until you fill all the bits, at which point you reach -1. When you increment -1, you get zero again and the cycle repeats.

这张环形图解释了它的原理。图中每个箭头代表递增一。正数比较小的时候，一切正常，直到数字填满了除最高有效位之外的所有位——这就是 32 位有符号整数能表示的**最大正值**。再递增一就溢出到最高有效位了，数字变成负数。实际上它变成了 32 位能表示的**最小负数**。继续递增，数值会越来越不那么负，直到所有位都填满，这时候值是 -1。再递增 -1，又回到零，循环往复。

---

So back to our debug session, let's set the counter value to -1 and watch the content of the R1 register. Next, let your program increment the counter one more time and close the cycle by making the counter zero again.

回到调试会话，把计数器设为 -1，看看 R1 寄存器的内容。然后再让程序递增一次，计数器归零，闭合这个循环。

---

Exit the debugger by pressing the X button.

按 X 按钮退出调试器。

课后作业：研究一下**无符号整数**（unsigned integers）的计数。做法是把 counter 变量的类型改成 `unsigned int`，重新编译，然后像刚才那样启动调试器。

In the dialogue box, choose the Debugger category and from the drop-down list, select the TI Stellaris option. Next, click on the Download tab and check the Use Flash Loader option as well as the Verify Download option. Click OK.

最后，作为本课的收尾，我来演示如何在 LaunchPad 开发板上运行代码。需要修改项目选项：点 Project > Options 菜单，在对话框里选 Debugger 类别，从下拉列表选 TI Stellaris。然后切到 Download 选项卡，勾选 Use Flash Loader 和 Verify Download。点 OK。

At this point you need to connect the Launchpad board to your computer by means of the provided USB cable. If this is the first time you connect the board, allow a minute or two for the installation of the USB driver for the USB debugger. The board is preloaded with a demo program that blinks the LED.

现在用配套的 USB 线把 LaunchPad 开发板连到电脑上。如果是第一次连接，等一两分钟让 USB 调试器驱动装好。开发板出厂时预装了一个 LED 闪烁的演示程序。

---

Now you can download your code to the **flash memory** of your board and start debugging in the exact same way as you did on the simulator. This is rather cool when you think about it, and it's only possible because both the USB debugger on the board and the microcontroller itself have special circuitry to provide this capability for you.

现在你可以把代码下载到开发板的**闪存**（flash memory）里，然后跟模拟器上一样开始调试。想想还挺酷的——这之所以能做到，是因为开发板上的 USB 调试器和微控制器本身都有专门的电路来支持这个功能。

---

Please note that your program stays permanently programmed inside the microcontroller, so it will count but it won't blink anymore. Don't despair though, we will make it blink and much more in the future.

注意，你的程序会永久保存在微控制器里，所以它会计数但不会再让 LED 闪烁了。别灰心，以后我们会让它闪烁，而且会做更多有趣的事。

| variable | 变量 | 内存中存储值的位置 |
| register | 寄存器 | 处理器内部的高速存储单元 |
| Program Counter (PC) | 程序计数器 | 跟踪当前执行指令地址的寄存器 |
| machine instruction | 机器指令 | CPU 可直接执行的二进制指令 |
| instruction mnemonic | 指令助记符 | 机器指令的人类可读表示 |
| memory address | 内存地址 | 分配给内存中每个字节的编号 |
| pre-increment | 前置递增 | `++` 运算符放在变量前面 |
| decimal system | 十进制 | 基数为 10 的计数系统 |
| hexadecimal system | 十六进制 | 基数为 16 的计数系统，C 语言用 `0x` 前缀表示 |
| binary system | 二进制 | 基数为 2 的计数系统 |
| nibble | 半字节 | 4 位二进制数据 |
| byte | 字节 | 8 位二进制数据 |
| two's complement | 二进制补码 | 计算机中表示有符号整数的方法 |
| signed integer | 有符号整数 | 可以表示正负值的整数类型 |
| unsigned integer | 无符号整数 | 只能表示非负值的整数类型 |
| flash memory | 闪存 | 可电擦除和重写的非易失性存储器 |
| control flow | 控制流 | 程序执行的顺序和路径 |
| simulator | 模拟器 | 在软件中模拟硬件行为的工具 |
| optimization | 优化 | 编译器对代码进行的性能改进 |
